# 移动端网站开发计划

## 一、概述

在现有 PC 端积分商城系统基础上，开发一套功能对等、体验优化的移动端网站（Mobile Web），覆盖管理员、店铺用户、普通用户三个角色。

### 核心目标

1. **功能对等** — 移动端与 PC 端功能完全一致
2. **多主题色系** — 5 种主题色（冰蓝/极光紫/翠绿/玫瑰/琥珀）+ 暗色/亮色模式切换
3. **原生感交互** — 底部 Tab 导航、左滑返回、下拉刷新、触控优化
4. **同一后端** — 复用现有 `http://localhost:18780` API

---

## 二、技术方案

### 2.1 架构决策

| 选项 | 方案 | 说明 |
|------|------|------|
| ✅ **选型** | 独立前端项目 | 新建 `code/mobile/`，与 PC 端 `code/frontend/` 完全隔离 |
| 备选 | 同一项目 | 已排除——用户要求互不影响 |

**理由**：完全隔离避免路由冲突、依赖冲突、构建配置互相影响；各自可独立部署迭代。

### 2.2 技术栈

| 类别 | 技术 | 说明 |
|------|------|------|
| 框架 | React 19 + TypeScript | 与 PC 端一致，降低心智负担 |
| 构建 | Vite | 独立配置 |
| 样式 | Tailwind CSS 4 + CSS 变量主题 | 完全自建主题系统（参考 PC 端和 demo） |
| 路由 | React Router 7 | 独立路由配置 |
| 状态 | Zustand | 新建 store |
| HTTP | Axios | 新建 request 封装 |
| 图标 | Lucide React | 独立安装 |
| 组件 | 自建移动端组件库 | 轻量、针对触控优化 |

> **注意**：stores / services / types / lib **不共用**，但严格参照 PC 端的 API 签名和类型定义进行开发，确保对接同一后端。

### 2.3 项目结构

```
code/
├── frontend/          ← PC 端（不变，不受影响）
│   ├── src/
│   │   ├── pages/

│   │   └── ...

│
└── mobile/            ← 新建：移动端（完全独立）
    ├── src/
    │   ├── layouts/       # 移动端布局（底部 Tab）
    │   ├── pages/         # 按角色分：auth/admin/operator/user/

    │   ├── stores/        # 独立 store（参照 PC 端 API 签名）

    │   ├── types/         # 独立类型定义
    │   ├── lib/           # 工具函数
    │   ├── router/        # 独立路由

    │   └── index.css
    ├── package.json

```

## 五、UI/UX 设计

### 5.1 视觉风格

沿用并强化 PC 端的 **Aurora Ice（极光冻彩）** 设计语言：

| 设计要素 | 说明 |
|---------|------|
| 背景 | 暗色/亮色自适应 + 毛玻璃效果 |
| 主题色 | 5 种可切换：冰蓝(`#3b82f6`)、极光紫(`#8b5cf6`)、翠绿(`#10b981`)、玫瑰(`#f43f5e`)、琥珀(`#f59e0b`) |
| 模式 | 暗色/亮色一键切换 |
| 卡片 | 毛玻璃(`backdrop-filter: blur`) + 半透明边框 |
| 圆角 | 统一大圆角（12-16px），按钮更大便于触控 |
| 字体 | 系统无衬线字体 |

### 5.2 主题切换交互

参考 `demo/login-a-switchable.html`，所有页面右下角（或页面底部 Tab 栏左侧）悬浮主题切换按钮：
- 暗色/亮色切换
- 5 种主题色快速选择
- 状态持久化到 `localStorage`

### 5.3 移动端专属交互

| 交互 | 实现方式 |
|------|---------|
| 底部 Tab 导航 | 固定底部，角色自适应 |
| 顶部导航栏 | 固定顶部，显示页面标题 + 左侧返回按钮 |
| 触控反馈 | 点击态 `active:scale-95`、按钮更大（min-height: 44px） |
| 下拉刷新 | 商品列表/订单列表支持下拉刷新 |
| 无限滚动 | 列表分页使用滚动加载代替分页按钮 |
| 滑动操作 | 订单列表可左滑取消/完成（渐进增强） |
| 底部弹出面板 | 选择器、确认对话框用 `bottom-sheet` 样式 |
| 输入优化 | `inputMode` 适配数字/文本输入类型 |

### 5.4 响应式基准

- 最小宽度：320px（iPhone SE）
- 设计基准：375px（iPhone 12/13/14）
- 最大宽度：480px（大屏手机）
- 超过 480px 自动显示 PC 版布局

## 十三、风险与注意事项

| 风险 | 影响 | 应对 |
|------|------|------|
| 移动端图片资源加载 | 商品主图/详情图在弱网下体验差 | 使用 `loading="lazy"` + 骨架屏占位 |
| 长表单（商品编辑） | 字段多、滚动长 | 分段表单 + 分组折叠 |
| 订单状态实时更新 | 用户期望数据实时 | 进入页面时自动刷新 + 下拉刷新 |
| ID 精度（雪花ID） | 后端返回 Long，前端需 String | 复用已有类型定义确保 `id: string` |
| 逻辑删除查询 | 需要过滤 `deleted=0` | 后端已处理，前端无需关心 |
