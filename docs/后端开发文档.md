## 四、数据库规范

| 规范 | 说明 |
|------|------|
| 不使用物理外键 | 通过逻辑关联维护数据一致性 |
| 不使用唯一键 | 逻辑删除后无法保证唯一性 |
| 枚举类型 | 用 `tinyint` + 备注替代枚举 |
| 删除方式 | 逻辑删除，所有表都有 `deleted` 字段 |
| ID 生成 | 雪花算法，转 String 传给前端 |
| 审计字段 | 所有表必须包含 `created_at`, `updated_at`, `created_by`, `updated_by`（纯关联表可酌情省略 `updated_at`） |

## 五、审计字段规范

### 5.1 字段约定

所有业务表必须包含以下 4 个审计字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `created_at` | DATETIME | 创建时间，`DEFAULT CURRENT_TIMESTAMP` |
| `updated_at` | DATETIME | 更新时间，`DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` |
| `created_by` | BIGINT | 创建人ID，指向 `user.id` |
| `updated_by` | BIGINT | 更新人ID，指向 `user.id` |

> 纯关联表（如多对多中间表）可酌情省略 `updated_at`、`created_by`、`updated_by`，但必须保留 `created_at`。

### 5.2 自动填充机制

项目通过 MyBatis-Plus 的 `MetaObjectHandler` 实现审计字段自动填充：

- `BaseEntity.java` 声明了 `createdAt`、`updatedAt`、`createdBy`、`updatedBy` 四个字段，并配置了 `@TableField(fill = ...)` 注解
- `MyMetaObjectHandler.java` 在 `insertFill` / `updateFill` 中自动写入当前时间和当前用户ID
- 当前用户ID 从请求属性 `userId` 获取（由 `AuthInterceptor` 拦截器解析 JWT 后注入）
- 非请求上下文（如注册、定时任务）时，`created_by` / `updated_by` 为 `NULL`

### 5.3 新建流程

1. 实体类继承 `BaseEntity<T>`
2. 在 `init.sql` 中添加对应的 4 个审计字段
3. 无需手动处理时间和用户，`MetaObjectHandler` 自动填充

## 十、注意事项

1. **雪花ID精度**：返回 Long 给前端时需转为 String，避免精度丢失
2. **逻辑删除**：查询时注意 `deleted = 0` 条件
3. **店铺营业状态**：歇业时普通用户可浏览但无法下单
4. **邀请码**：管理员/店铺用户可生成，普通用户注册需审核

## 十一、错误处理规范

### 11.1 统一响应结构

所有 API 响应统一使用 `Result<T>` 包装：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}

{
  "code": 1006,
  "message": "邀请码无效",
  "data": null
}
```

### 11.2 错误码规范

| 区间 | 类别 | 说明 |
|------|------|------|
| 200 | 成功 | - |
| 400 | HTTP 错误 | 仅通用失败 |
| 401 | 未认证 | Token 失效 |
| 403 | 无权限 | 无访问权限 |
| 500 | 服务器错误 | 兜底 |
| 1000-1099 | 认证模块 | 登录、注册、Token |
| 1100-1199 | 验证异常 | 参数校验、格式错误 |
| 2000-2999 | 业务错误 | 商品、订单、积分等 |

### 11.4 全局异常处理

项目使用 `@RestControllerAdvice` 的 `GlobalExceptionHandler` 统一处理异常：

| 异常类型 | 处理方式 |
|---------|---------|
| `MethodArgumentNotValidException` | 取第一条字段错误，返回 `PARAM_VALID_FAIL` |
| `InvalidFormatException` | JSON 类型转换失败，返回 `REQUEST_FORMAT_ERROR` |
| `MissingServletRequestParameterException` | 缺少参数，返回 `MISSING_PARAM` |
| `MethodArgumentTypeMismatchException` | 参数类型错误，返回 `REQUEST_FORMAT_ERROR` |
| `HandlerMethodValidationException` | 路径参数校验失败，返回 `PARAM_VALID_FAIL` |
| `BusinessException` | 业务异常，返回自定义码和消息 |
| `Exception`（兜底） | 记日志，返回 `SERVER_ERROR` |

### 11.5 Service 层错误返回

Service 层通过 `Result.fail(错误码, 消息)` 直接返回错误，Controller 原样返回给客户端。

```java
// ✅ 正确：Service 层直接返回
return Result.fail(ResultCode.PRODUCT_NOT_FOUND, "商品不存在");

// ✅ 正确：需要抛出业务异常时
throw new BusinessException(ResultCode.INVITE_CODE_INVALID, "邀请码无效");

// ❌ 错误：不要在 Service 层抛异常让 GlobalExceptionHandler 捕获
// 因为 Controller 直接返回 Result，异常不会飞到拦截器
```

## 十二、编码规范：禁止硬编码，统一使用枚举

### 12.1 核心原则

> **代码中严禁出现魔数/魔字符串，所有状态、类型、角色等固定取值必须使用枚举。**

### 12.2 枚举定义规范

所有枚举类统一放在 `entity/enums/` 包下，遵循以下模式：

```java
public enum OrderStatus {
    CREATED(1, "已下单"),
    CONFIRMED(2, "已确认"),
    SHIPPED(3, "已发货"),
    COMPLETED(4, "已完成"),
    CLOSED(5, "已关闭");

    private final int code;
    private final String desc;

    OrderStatus(int code, String desc) {
        this.code = code;
        this.desc = desc;
    }

    public int getCode() { return code; }
    public String getDesc() { return desc; }

    public static OrderStatus fromCode(int code) {
        for (OrderStatus e : values()) {
            if (e.code == code) return e;
        }
        return null;
    }
}
```

错误码使用 `ResultCode` 常量类，禁止直接硬编码错误码数字。

### 12.3 使用示例

```java
// ✅ 正确：使用枚举引用
if (product.getStatus() == ProductStatus.ON_SALE.getCode()) { ... }
if (shop.getStatus() == ShopStatus.APPROVED.getCode()) { ... }

// ❌ 错误：硬编码魔数
if (product.getStatus() == 1) { ... }
if (shop.getStatus() == 2) { ... }

// ✅ 正确：使用 ResultCode 常量
return Result.fail(ResultCode.PRODUCT_NOT_FOUND, "商品不存在");

// ❌ 错误：硬编码错误码
return Result.fail(2003, "商品不存在");
```

| 枚举类 | 所在文件 | 覆盖场景 |
|--------|---------|---------|

### 12.5 审核清单

提交代码前检查：
- [ ] 新增的状态/类型是否定义了对应的枚举？
