# 后端开发文档

## 项目信息

- **技术栈**: Spring Boot 3.2.12 (Java 21), MyBatis-Plus 3.5.16, MySQL 8.0, Redis, JWT
- **构建工具**: Maven
- **端口**: 8080
- **目录**: `code/backend/ai-shop/`

## 常用命令

```bash
cd code/backend/ai-shop
./mvnw spring-boot:run          # 开发服务器
./mvnw clean package            # 构建
./mvnw test                     # 测试
./mvnw test -Dtest=AuthServiceTest  # 运行单个测试类
```

## 核心规范

### 1. 雪花 ID 序列化（最高优先级）

所有实体继承 `BaseEntity`，`id` 字段已配置：

```java
@TableId(type = IdType.ASSIGN_ID)
@JsonSerialize(using = ToStringSerializer.class)
protected Long id;
```

**关键约束**:
- 后端 ID 在 JSON 序列化时转为 String（防止 JS 精度丢失）
- 如果新增 ID 字段（如 `shopId`, `userId`）是外键，必须同样添加 `@JsonSerialize(using = ToStringSerializer.class)`

### 2. 逻辑删除

```java
@TableLogic
protected Integer deleted = 0;
```

MyBatis-Plus 自动过滤 `deleted = 0` 的记录，无需手动添加条件。

### 3. 审计字段

所有表包含 `createdAt`, `updatedAt`, `createdBy`, `updatedBy`，通过 `MyMetaObjectHandler` 自动填充：

```java
// 从请求属性获取当前用户 ID
Long userId = (Long) request.getAttribute("userId");
```

### 4. 枚举类规范

| 枚举 | 值 | 说明 |
|------|-----|------|
| RoleEnum | 1=管理员, 2=店铺用户, 3=普通用户 | 用户角色 |
| UserStatus | 1=待审核, 2=正常, 3=冻结 | 用户状态 |
| ShopStatus | 1=待审核, 2=已通过, 3=已拒绝, 4=已禁用 | 店铺状态 |
| ProductStatus | 0=下架, 1=上架 | 商品状态 |
| ProductType | 1=虚拟, 2=实物 | 商品类型 |
| OrderStatus | 1=已下单, 2=已确认, 3=已发货, 4=已完成, 5=已关闭 | 订单状态 |
| PointsType | 1=发放, 2=扣除, 3=兑换, 4=退款 | 积分类型 |
| MessageType | - | 消息类型 |
| InviteCodeStatus | 0=未使用, 1=已使用 | 邀请码状态 |
| FileStorageType | 1=本地, 2=OSS | 存储类型 |

**禁止硬编码**，Service 层必须使用枚举：

```java
// ✅ 正确
if (user.getStatus() != UserStatus.NORMAL.getCode()) {
    throw new BusinessException("用户未审核通过");
}

// ❌ 错误
if (user.getStatus() != 2) {
    throw new BusinessException("用户未审核通过");
}
```

## API 接口约定

### 前缀与角色

| 前缀 | 说明 | 认证 |
|------|------|------|
| `/api/auth` | 认证 | 无需认证 |
| `/api/admin` | 管理员 | role=1 |
| `/api/operator` | 店铺用户 | role=2 |
| `/api/user` | 普通用户 | role=3 |
| `/api/file` | 文件 | 无需认证 |

### 统一响应格式

```java
// 成功
Result.success(data)
Result.success(data, "自定义消息")

// 失败
Result.fail(ResultCode.XXX, "错误消息")
Result.fail(ResultCode.FAIL, "操作失败")
```

### ResultCode 错误码

| 区间 | 说明 |
|------|------|
| 200 | 成功 |
| 400 | 通用失败 |
| 401 | 未认证 |
| 403 | 无权限 |
| 500 | 服务器错误 |
| 1000-1099 | 认证模块 |
| 1100-1199 | 验证异常 |
| 2000-2999 | 业务错误 |

## 数据库规范

- **不使用物理外键**，通过逻辑关联
- **不使用唯一键**（逻辑删除后无法保证唯一性）
- 用 `tinyint` + 备注替代枚举
- ID 使用雪花算法
- 订单表为 `orders`（非 `order`）
- 修改实体/表结构后必须同步更新 `sql/init.sql`

## 分层开发模式

### Controller 层

```java
@RestController
@RequestMapping("/api/xxx")
public class XxxController {

    private final XxxService xxxService;

    public XxxController(XxxService xxxService) {
        this.xxxService = xxxService;
    }

    // 查询
    @GetMapping("/{id}")
    public Result<XxxDTO> getById(@PathVariable Long id) {
        return Result.success(xxxService.getById(id));
    }

    // 分页查询
    @GetMapping("/page")
    public Result<PageResult<XxxDTO>> page(PageRequest request) {
        return Result.success(xxxService.page(request));
    }

    // 创建
    @PostMapping
    public Result<Void> create(@RequestBody XxxDTO dto) {
        xxxService.create(dto);
        return Result.success();
    }

    // 更新
    @PutMapping("/{id}")
    public Result<Void> update(@PathVariable Long id, @RequestBody XxxDTO dto) {
        dto.setId(id);
        xxxService.update(dto);
        return Result.success();
    }

    // 删除
    @DeleteMapping("/{id}")
    public Result<Void> delete(@PathVariable Long id) {
        xxxService.delete(id);
        return Result.success();
    }
}
```

### Service 层

```java
@Service
public class XxxService {

    private final XxxMapper xxxMapper;

    public XxxService(XxxMapper xxxMapper) {
        this.xxxMapper = xxxMapper;
    }

    public XxxDTO getById(Long id) {
        Xxx entity = xxxMapper.selectById(id);
        if (entity == null) {
            throw new BusinessException(ResultCode.DATA_NOT_FOUND, "数据不存在");
        }
        return BeanUtil.copy(entity, XxxDTO.class);
    }

    public void create(XxxDTO dto) {
        // 参数校验
        validate(dto);

        // 转换并保存
        Xxx entity = BeanUtil.copy(dto, Xxx.class);
        xxxMapper.insert(entity);
    }
}
```

### Mapper 层

```java
@Mapper
public interface XxxMapper extends BaseMapper<Xxx> {
}
```

### DTO 转换

使用 `BeanUtil.copy(source, targetClass)` 工具类进行对象转换。

## AI 自检清单

开发或修改代码后，按以下清单自检：

### 实体层检查

- [ ] ID 字段是否添加 `@JsonSerialize(using = ToStringSerializer.class)`
- [ ] 外键 ID 字段是否也需要 String 序列化
- [ ] 是否继承了 `BaseEntity`
- [ ] 枚举字段是否使用 `tinyint`

### Service 层检查

- [ ] 是否使用枚举而非硬编码
- [ ] 是否正确处理空值和边界情况
- [ ] `deleted` 字段是否自动过滤

### Controller 层检查

- [ ] 请求路径是否正确（前缀匹配角色）
- [ ] 权限注解是否正确添加
- [ ] 分页参数是否使用 `PageRequest`

### 数据库同步检查

- [ ] `sql/init.sql` 是否与实体类同步
- [ ] 是否添加了必要的索引

### API 一致性检查

- [ ] 前端 `types/api.ts` 类型是否与后端 DTO 一致
- [ ] 错误码是否已定义
- [ ] 分页返回结构是否匹配

### 测试检查

- [ ] 新增功能是否有对应测试
- [ ] 测试是否能通过

## AI 开发流程

### 1. 新增实体

1. 创建实体类，继承 `BaseEntity`
2. 定义枚举（如有状态字段）
3. 创建 Mapper 接口
4. 创建 Service
5. 创建 Controller
6. 同步 `sql/init.sql`
7. 添加单元测试
8. 通知前端同步类型定义

### 2. 新增 API

1. 确定 API 路径前缀（按角色）
2. 在 Controller 添加接口
3. Service 处理业务逻辑
4. 使用 `Result.fail(ResultCode.XXX, "消息")` 返回错误
5. 添加必要的参数校验
6. 更新自检清单

### 3. 修改现有功能

1. 确认修改范围
2. 同步修改实体类和 `sql/init.sql`
3. 更新 DTO
4. 更新 Service
5. 更新 Controller
6. 确保测试通过

### 4. 自检脚本

```
后端自检清单:
□ 实体类 ID 序列化正确
□ 枚举使用正确
□ API 路径前缀正确
□ 错误码已定义
□ SQL 脚本已同步
□ 单元测试通过
□ 前端类型已同步
```

| 问题 | 检查点 |
|------|------|
