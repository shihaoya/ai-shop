# 后端开发文档

## 一、技术栈

| 类别 | 技术 | 说明 |
|------|------|------|
| 框架 | Spring Boot 3.x | Java 17 |
| ORM | MyBatis-Plus | 简化 CRUD 操作 |
| 数据库 | MySQL 8.0 | 逻辑删除，不使用物理外键 |
| ID 生成 | 雪花算法 | 转 String 传给前端避免精度丢失 |
| 安全 | JWT | Token 认证 |
| 构建 | Maven | 依赖管理和构建 |

## 四、数据库规范

| 规范 | 说明 |
|------|------|
| 不使用物理外键 | 通过逻辑关联维护数据一致性 |
| 不使用唯一键 | 逻辑删除后无法保证唯一性 |
| 枚举类型 | 用 `tinyint` + 备注替代枚举 |
| 删除方式 | 逻辑删除，所有表都有 `deleted` 字段 |
| ID 生成 | 雪花算法，转 String 传给前端 |

   关闭(5)     关闭(5)

## 九、注意事项

1. **雪花ID精度**：返回 Long 给前端时需转为 String，避免精度丢失
2. **逻辑删除**：查询时注意 `deleted = 0` 条件
3. **店铺营业状态**：歇业时普通用户可浏览但无法下单
4. **邀请码**：管理员/店铺用户可生成，普通用户注册需审核

## 十、错误处理规范

### 10.1 统一响应结构

所有 API 响应统一使用 `Result<T>` 包装：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}

{
  "code": 1006,
  "message": "邀请码无效",
  "data": null
}
```

### 10.2 错误码规范

| 区间 | 类别 | 说明 |
|------|------|------|
| 200 | 成功 | - |
| 400 | HTTP 错误 | 仅通用失败 |
| 401 | 未认证 | Token 失效 |
| 403 | 无权限 | 无访问权限 |
| 500 | 服务器错误 | 兜底 |
| 1000-1099 | 认证模块 | 登录、注册、Token |
| 1100-1199 | 验证异常 | 参数校验、格式错误 |
| 2000-2999 | 业务错误 | 商品、订单、积分等 |

### 10.3 错误码清单

**通用错误码**：

| 错误码 | 常量名 | 说明 |
|-------|--------|------|
| 200 | SUCCESS | 成功 |
| 400 | FAIL | 通用失败 |
| 401 | UNAUTHORIZED | 未认证 |
| 403 | FORBIDDEN | 无权限 |
| 404 | NOT_FOUND | 资源不存在 |
| 500 | SERVER_ERROR | 服务器错误 |

**认证模块 (1000-1099)**：

| 错误码 | 常量名 | 说明 |
|-------|--------|------|
| 1001 | USERNAME_PASSWORD_ERROR | 用户名或密码错误 |
| 1002 | USER_DISABLED | 账号已被禁用 |
| 1003 | USER_NOT_FOUND | 用户不存在 |
| 1004 | TOKEN_EXPIRED | Token已过期 |
| 1005 | TOKEN_INVALID | Token无效 |
| 1006 | INVITE_CODE_INVALID | 邀请码无效 |
| 1007 | USERNAME_EXISTS | 用户名已存在 |
| 1008 | PASSWORD_ERROR | 密码错误 |
| 1009 | PARAM_VALID_FAIL | 参数校验失败 |
| 1010 | PASSWORD_MISMATCH | 两次密码输入不一致 |

**验证异常 (1100-1199)**：

| 错误码 | 常量名 | 说明 |
|-------|--------|------|
| 1101 | REQUEST_FORMAT_ERROR | 请求格式错误 |
| 1102 | MISSING_PARAM | 缺少必要参数 |

**业务错误 (2000-2999)**：

| 错误码 | 常量名 | 说明 |
|-------|--------|------|
| 2001 | SHOP_NOT_FOUND | 店铺不存在 |
| 2002 | SHOP_NOT_APPROVED | 店铺未审核 |
| 2003 | PRODUCT_NOT_FOUND | 商品不存在 |
| 2004 | PRODUCT_OFF_SALE | 商品已下架 |
| 2005 | PRODUCT_STOCK_ZERO | 商品库存为0 |
| 2006 | POINTS_INSUFFICIENT | 积分不足 |
| 2007 | ORDER_NOT_FOUND | 订单不存在 |
| 2008 | ORDER_STATUS_ERROR | 订单状态错误 |
| 2009 | ADDRESS_NOT_FOUND | 地址不存在 |
| 2010 | CATEGORY_NOT_FOUND | 分类不存在 |
| 2011 | USER_NOT_APPROVED | 用户未审核 |

### 10.4 全局异常处理

项目使用 `@RestControllerAdvice` 的 `GlobalExceptionHandler` 统一处理异常：

| 异常类型 | 处理方式 |
|---------|---------|
| `MethodArgumentNotValidException` | 取第一条字段错误，返回 `PARAM_VALID_FAIL` |
| `InvalidFormatException` | JSON 类型转换失败，返回 `REQUEST_FORMAT_ERROR` |
| `MissingServletRequestParameterException` | 缺少参数，返回 `MISSING_PARAM` |
| `MethodArgumentTypeMismatchException` | 参数类型错误，返回 `REQUEST_FORMAT_ERROR` |
| `HandlerMethodValidationException` | 路径参数校验失败，返回 `PARAM_VALID_FAIL` |
| `BusinessException` | 业务异常，返回自定义码和消息 |
| `Exception`（兜底） | 记日志，返回 `SERVER_ERROR` |

### 10.5 Service 层错误返回

Service 层通过 `Result.fail(错误码, 消息)` 直接返回错误，Controller 原样返回给客户端。

```java
// ✅ 正确：Service 层直接返回
return Result.fail(ResultCode.PRODUCT_NOT_FOUND, "商品不存在");

// ✅ 正确：需要抛出业务异常时
throw new BusinessException(ResultCode.INVITE_CODE_INVALID, "邀请码无效");

// ❌ 错误：不要在 Service 层抛异常让 GlobalExceptionHandler 捕获
// 因为 Controller 直接返回 Result，异常不会飞到拦截器
```

`request.ts` 响应拦截器统一处理错误 toast 提示：
